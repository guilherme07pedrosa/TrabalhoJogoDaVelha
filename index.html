1. Visão geral

O sistema permite que dois jogadores, em máquinas diferentes, se encontrem por meio de um servidor de match e joguem uma partida de jogo da velha. Cada jogada é transmitida também para quantos displays estiverem ouvindo o canal multicast.

2. Módulos

Servidor de Match (MatchImpl)

Oferece um único método remoto, getOponent(json), definido na interface MatchIntf. O próprio programa cria o RMI Registry e registra o objeto com o nome MatchSrv.

  • O RMI atende cada chamada numa thread própria. Quando não há oponente, a chamada entra numa fila e a thread fica parada em wait().
  • Quando chega outro jogador com o mesmo protocolo, o servidor forma o par, preenche a resposta de quem esperava e o acorda com notifyAll(). Assim o return chega para os dois jogadores.
  • Quem já estava esperando recebe inicia: true; o outro recebe inicia: false. Os dois saem da fila.
  • Se ninguém aparecer no tempo limite (padrão de 60 s), o pedido sai da fila e o jogador recebe a exceção remota TimeoutMatchEx.

Jogador (Jogador)

  1. Abre um ServerSocket na porta informada (antes do match, para o oponente poder conectar logo).
  2. Chama getOponent e aguarda o retorno com o IP, a porta e quem inicia.
  3. Quem inicia conecta no oponente; o outro aceita a conexão.
  4. Os dois trocam jogadas pelo socket TCP até vitória, derrota ou empate. Cada jogada feita também é publicada no multicast.
  5. No fim, o socket é fechado.

Controle de jogadas inválidas. Ao receber uma jogada, o jogador confere:

  • se o Numero é o esperado;
  • se a casa existe (0 a 8) e está livre;
  • se o Tabuleiro recebido é igual ao tabuleiro local mais a jogada nova.

Se algo estiver errado, ele devolve a mesma mensagem sem incrementar o número e avisa o usuário. Quem recebe a própria mensagem de volta desfaz a jogada e joga de novo. Depois de 5 rejeições seguidas, a partida é encerrada. A mesma validação é feita localmente antes de enviar, então o usuário não consegue escolher uma casa ocupada ou inexistente.

Fim de jogo. Ao receber a jogada que dá vitória ao oponente, o jogador declara a derrota e responde com "Resultado": "der", aceitando o resultado. No empate, responde com "emp".

Modos: humano (padrão, o usuário digita a casa) e auto (joga na primeira casa livre; usado para testes).

Display (Display)

Entra no grupo multicast 225.1.1.4:8804 e, a cada mensagem recebida, desenha o tabuleiro em texto com o número da jogada, quem jogou e o resultado. Podem rodar vários displays ao mesmo tempo, em qualquer máquina.

Apoio (Json)

Monta e lê as mensagens JSON, procurando cada campo pelo nome, sem biblioteca externa.

3. Mensagens

Pedido de match (parâmetro de getOponent):

{"ip": "152.92.236.16", "porta": 7004, "protocolo": "tcp"}

Resposta do match:

{"ip": "152.92.236.17", "porta": 7004, "inicia": true}

Jogada (uma mensagem por linha no socket TCP, e a mesma no multicast):

{"Numero": 2, "Jogada": 8, "Tabuleiro": [1, 2, 0, 0, 1, 0, 0, 0, 1], "Resultado": "jog"}
CampoSignificado
NumeroNúmero da jogada, de 0 a 8. Começa em 0 e é incrementado por quem joga.
JogadaCasa jogada, de 0 a 8.
Tabuleiro9 posições: 0 = vazia, 1 = X (quem inicia), 2 = O.
Resultadojog (em andamento), vit (vitória), der (derrota aceita), emp (empate).

4. Como compilar e executar

Requer Java 17. Na pasta dos arquivos .java:

javac *.java

Nas máquinas virtuais (servidor e display na .14, jogadores na .16 e na .17):

# 152.92.236.14
java -Djava.rmi.server.hostname=152.92.236.14 MatchImpl 9804
java Display 152.92.236.14

# 152.92.236.16
java Jogador 152.92.236.14 9804 152.92.236.16 7004

# 152.92.236.17
java Jogador 152.92.236.14 9804 152.92.236.17 7004
ProgramaArgumentos
MatchImpl<portaRegistry> [timeoutSegundos]
Display[IP desta máquina]
Jogador<IP servidor> <portaRegistry> <meu IP> <minha porta> [humano|auto]

A opção -Djava.rmi.server.hostname faz o RMI informar aos clientes o IP real do servidor, e não um endereço local.

5. Timeouts e tratamento de falhas

SituaçãoTratamento
Nenhum oponente apareceApós 60 s, o pedido sai da fila e o jogador recebe TimeoutMatchEx.
Oponente não conecta após o matchQuem aguarda a conexão encerra após 60 s.
Oponente demora para jogarApós 5 min sem jogada, a partida é encerrada.
Oponente desconectaO jogador detecta o fim da conexão e encerra.
Sem confirmação no fim de jogoApós 30 s, o resultado é declarado sem confirmação.
Jogada inválida recebidaA mensagem é devolvida; 5 rejeições seguidas encerram a partida.
Falha no multicastO jogo continua sem publicar nos displays.

6. Limitações

  • O multicast usa UDP, sem garantia de entrega. Como cada mensagem leva o tabuleiro inteiro, um display que perder uma jogada se corrige na seguinte.
  • Se duas partidas acontecerem ao mesmo tempo, os displays mostram as jogadas das duas misturadas, pois a mensagem não identifica a partida.
  • Cada jogador disputa apenas uma partida e só o protocolo TCP foi implementado.
